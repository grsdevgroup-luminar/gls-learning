Resumable Video Upload Architecture

SkillStream · Cloudflare Stream tus migration · Decision log & flow reference · 2026-08-25

Summary

Replace the 200 MB basic multipart direct upload with tus resumable uploads for all video sizes up to 30 GiB. Introduce an application-owned Upload record as the source of truth for ownership, attachability, and playback readiness. Only initiation and completion handshakes pass through Nest; all file bytes go browser → Cloudflare.

Decision log

IDDecisionRationale
D1 Structured POST /media/tus with JSON body — not raw header proxy Server controls metadata, validation, rate limits, and Cloudflare API shape.
D2 Create Upload DB row before calling Cloudflare Every CF reservation has an application owner from birth; enables cleanup on partial failure.
D3 uid from stream-media-id header, not URL parsing Cloudflare-documented best practice.
D4 Tus for all uploads; legacy /media/upload-url removed (phase 4) One code path; resumability even for small files; no misleading 200 MB ceiling.
D5 Separate transport UI state from encoding/server state A paused upload ≠ a Cloudflare encoding failure.
D6 POST /media/uploads/:id/complete after tus onSuccess Lessons attach only PROCESSING or READY — never UPLOADING.
D7 Persist uploadId + uploadUrl in app draft storage, not only tus-js-client fingerprint store Cross-tab recovery, server-side cleanup correlation, no duplicate CF reservations on remount.
D8 Centralize attach validation in media.assertAttachableUpload() Single policy for addLesson / updateLesson; admin cannot accidentally bypass ownership.
D9 getPlayback() gates on local Upload.status === READY No per-play Cloudflare API call; honest “processing” UX.
D10 CF webhook: inspect video payload (readyToStream, status.state), verify Webhook-Signature Not Stripe-style named events; account-level infra config.
D11 Admins follow same ownership rules unless explicit future policy adds impersonation Prevents accidental cross-instructor UID attachment.
D12 Backfill legacy lessons: synthetic Upload rows marked READY Existing cfVideoUid values keep playing without CF round-trip.

Gap analysis — no blockers, four items to specify in implementation

1. Legacy playback

Lessons with cfVideoUid but no Upload row must not break. Migration backfills READY records; getPlayback treats missing row + existing UID as grandfathered READY until backfill completes.

2. Initiation partial failure

If Cloudflare succeeds but DB update fails, a maintenance sweep deletes unattached CF videos whose Upload row is stuck in CREATED without cloudflareUid or whose CF uid was written but row rolled back (reconcile via expiry).

3. Complete ↔ webhook race

Both paths idempotently advance status. Allowed transitions are monotonic: UPLOADING → PROCESSING → READY or → FAILED. Duplicate calls are no-ops.

4. New-course drafts

courseId is optional at initiation (course may not exist yet). lessonId stays null until save. Attach validation uses ownerUserId + status; optional courseId constraint applies only when provided and course exists.

Database: Upload table

model Upload {
  id            String       @id @default(cuid())
  ownerUserId   String
  owner         User         @relation(fields: [ownerUserId], references: [id])
  cloudflareUid String?      @unique
  courseId      String?      // optional draft association
  course        Course?      @relation(...)
  lessonId      String?      @unique  // one upload → one lesson max
  lesson        Lesson?      @relation(...)
  filename      String
  bytes         BigInt
  fileFingerprint String?    // name+size+lastModified hash for resume
  status        UploadStatus @default(CREATED)
  failureReason String?
  createdAt     DateTime     @default(now())
  updatedAt     DateTime     @updatedAt
  expiresAt     DateTime
  completedAt   DateTime?    // tus bytes complete
  readyAt       DateTime?    // webhook: readyToStream

  @@index([ownerUserId, status])
  @@index([status, expiresAt])
  @@index([courseId])
}

enum UploadStatus {
  CREATED
  UPLOADING
  PROCESSING
  READY
  FAILED
  ABANDONED
}
FieldPurpose
uploadId (PK)Application identity returned to client; never changes.
cloudflareUidFrom stream-media-id; becomes Lesson.cfVideoUid.
lessonId uniquePrevents two lessons sharing one upload; set transactionally on attach.
fileFingerprintResume key: sha256(name|size|lastModified) — no full-file hash.
expiresAtCF reservation expiry + app policy; stale UPLOADING swept after grace window.

State machines (kept separate)

Server / encoding (Upload.status)

CREATED→ UPLOADING→ PROCESSING→ READY
UPLOADING→ ABANDONED | PROCESSING→ FAILED

Client transport (VideoUpload component)

idle→ uploading⇄ paused→ retrying→ uploaded
encoding: unknown→ processing→ playable | failed

onUploaded({ uploadId, uid }) fires at transport uploaded (after /complete returns). Encoding state comes from polling upload status or webhook-driven cache.

POST /media/tus — request & response

Request: { filename, bytes, maxDurationSeconds?, courseId? } Validation: • extension in [.mp4, .mov, .webm, ...] • 0 < bytes ≤ 30 GiB • maxDurationSeconds ≤ server cap (7200) • courseId → assertCourseAccess if present • rate limit + max N outstanding UPLOADING per user Server: 1. INSERT Upload (CREATED) 2. POST CF .../stream?direct_user=true Headers: Tus-Resumable, Upload-Length, Upload-Metadata, Upload-Creator 3. UPDATE Upload → UPLOADING, cloudflareUid, expiresAt 4. Return TusUploadDto Response: { uploadId, uploadUrl, uid, expiresAt }

Resume & remount recovery

Draft storage key: skillstream:upload-draft:{courseId|new}:{lessonId}

Stored JSON: { uploadId, uploadUrl, uid, fileFingerprint, expiresAt }

On file select: 1. fingerprint = hash(name + size + lastModified) 2. read draft storage for this lesson slot 3. IF draft exists AND fingerprint matches AND now < expiresAt: → tus.Upload({ uploadUrl, ... }) + resume ELSE IF draft expired: → DELETE /media/uploads/:uploadId (best effort) + clear draft 4. ELSE: → POST /media/tus → save draft → start tus On remount (page reload): → restore draft from localStorage → if file re-selected with same fingerprint, resume without new POST /media/tus Browser close: → do NOT mark ABANDONED (resume window remains open)

Ownership & lesson attach

authoring.addLesson / updateLesson │ ▼ media.assertAttachableUpload({ uid, user, courseId, lessonId? }) │ ├─ Upload.cloudflareUid === uid ├─ Upload.ownerUserId === user.id (admins: same rule — no cross-owner) ├─ Upload.status IN (PROCESSING, READY) ├─ Upload.lessonId IS NULL OR === lessonId being edited └─ Upload.courseId IS NULL OR === courseId (when provided) │ ▼ $transaction: write Lesson.cfVideoUid UPDATE Upload SET lessonId = :lessonId │ ▼ if replacing old cfVideoUid: queue async CF delete if old uid unreferenced

Cloudflare webhook handler

Verification

  • Read raw body (existing rawBody: true in main.ts)
  • Parse Webhook-Signature: time=<ts>,sig1=<hmac>
  • HMAC-SHA256 over <time>.<rawBody>
  • Reject stale timestamps (e.g. > 5 min)
  • Constant-time compare

Payload handling

  • Extract uid from video object
  • If readyToStream → READY
  • If status.state indicates error → FAILED
  • Lookup Upload by cloudflareUid
  • Idempotent status update (sync, fast)
  • Queue: notify instructor, no blocking work

Infra Configure webhook URL once per Cloudflare account. Add CLOUDFLARE_STREAM_WEBHOOK_SECRET to env.

Playback readiness

getPlayback(lessonId): lesson = findLesson(...) uid = lesson.cfVideoUid upload = findUploadByCloudflareUid(uid) if upload exists: ready = (upload.status === READY) else: ready = !!uid // grandfathered pre-migration if !ready: return { ready: false, hlsUrl: null, iframeUrl: null, ... } return signed playback URLs

Implementation phases

  1. Phase 1 — Upload schema & ownership Prisma model + migration + backfill script for existing cfVideoUid. UploadRepository. assertAttachableUpload() wired into authoring. Shared contracts in @skillstream/shared.
  2. Phase 2 — Tus initiation & completion POST /media/tus, POST /complete, GET, DELETE. Env vars. Rate limits. E2E auth tests.
  3. Phase 3 — Frontend tus-js-client Rewrite VideoUpload. Draft localStorage. Pause / Discard UX. onUploaded contract. Course builder stores uploadId. Add tus-js-client dependency. 30 GiB cap.
  4. Phase 4 — Remove basic upload ✓ Deleted createDirectUpload, /media/upload-url; updated e2e + docs.
  5. Phase 5 — Playback gate ✓ getPlayback() checks Upload status; grandfathered lessons without an Upload row still play.
  6. Phase 6 — Webhook ✓ POST /webhooks/cloudflare-stream with Webhook-Signature verification and PROCESSING → READY/FAILED sync.
  7. Phase 7 — Cleanup jobs Replacement delete on lesson update/delete. Maintenance sweep for orphans. FAILED retention policy.
